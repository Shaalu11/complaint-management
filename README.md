# Hostel Complaint Management API

A FastAPI-based backend system for managing hostel complaints.

## Features

- Student signup and login
- JWT authentication
- Password hashing
- Complaint creation
- Complaint retrieval
- Complaint update
- Complaint deletion
- Complaint search
- Complaint filtering
- Pagination
- Notification service
- Escalation service
- PostgreSQL database
- Alembic migrations
- Automated tests
- Swagger/OpenAPI documentation

## Installation

Clone the repository and enter the project directory.

Create a virtual environment:

python -m venv .venv

Activate it on Windows:

.venv\Scripts\activate

Install dependencies:

pip install -r requirements.txt

## Environment Variables

Create a .env file:

JWT_SECRET_KEY=your-secret-key
JWT_ALGORITHM=HS256

Do not commit .env to version control.

## Database Setup

Create a PostgreSQL database named:

hostel_db

Configure the database connection in database.py.

Run the Alembic migrations:

alembic upgrade head
## Running the API

Start the development server:

uvicorn main:app --reload

The API will be available at:

http://127.0.0.1:8000

Swagger documentation:

http://127.0.0.1:8000/docs

ReDoc documentation:

http://127.0.0.1:8000/redoc
## Authentication

The API uses JWT Bearer authentication.

First register a student using:

POST /signup

Then authenticate using:

POST /login

The returned access token must be supplied to protected endpoints.

In Swagger, click:

Authorize

and enter:

Bearer <access_token>
## API Endpoints
System
GET /health

Checks whether the API is running.

Example response:

{
  "status": "success"
}
Authentication
POST /signup

Creates a new student account.

Example request:

{
  "username": "student01",
  "password": "password123",
  "name": "Student One",
  "email": "student01@example.com",
  "room_number": "A101"
}
POST /login

Authenticates a student.

The endpoint uses form data.

Example:

username=student01
password=password123

Example response:

{
  "access_token": "JWT_TOKEN",
  "token_type": "bearer"
}
Complaints
POST /complaints

Creates a complaint for the authenticated student.

Requires:

Authorization: Bearer <access_token>

Example request:

{
  "title": "Broken fan",
  "description": "The fan is not working",
  "category": "Electrical"
}
GET /complaints

Retrieves complaints.

Supported query parameters:

category
status
search
skip
limit

Example:

GET /complaints?category=Electrical

Example:

GET /complaints?status=Pending

Example:

GET /complaints?search=fan

Example with pagination:

GET /complaints?skip=0&limit=10
GET /complaints/{complaint_id}

Retrieves a specific complaint.

Example:

GET /complaints/7

Requires authentication.

PATCH /complaints/{complaint_id}

Updates an existing complaint.

Example:

{
  "description": "The fan has completely stopped working",
  "status": "Pending"
}

Requires authentication.

DELETE /complaints/{complaint_id}

Deletes a complaint.

Example:

DELETE /complaints/7

Requires authentication.

## Testing

Run the automated tests using:

pytest

The test suite uses an isolated asynchronous SQLite database.

The tests cover:

Student signup
Duplicate username validation
Login
Invalid login
Complaint creation
Unauthorized requests
Complaint ownership authorization
Search and filtering
Notification service integration
## Database Migrations

Create a new migration:

alembic revision --autogenerate -m "describe change"

Apply migrations:

alembic upgrade head

Check current migration:

alembic current

View migration history:

alembic history
